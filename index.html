01

This already happened

In 2024 a security researcher noticed that AI models kept recommending pip install huggingface-cli. The real library installs under a different name. That package had never existed.

He registered it as an empty placeholder, just to see what would happen.

It received more than 30,000 downloads in three months. Alibaba had pasted the hallucinated command straight into the README of a public repository.

The package was harmless. It did not have to be. Anything installed from a registry can run code on the machine that installs it — including your build server.

The attack is called slopsquatting. Unlike typosquatting, it does not bet on human typos — it bets on the names machines invent.

19.7%
of 2.23 million AI-generated code samples contained at least one hallucinated package — 16 models, Python and JavaScript.
43%

5%

Sources: USENIX Security 2025; 2026 re-evaluation against live PyPI and npm.

02

What it checks, on every pull request

Findings arrive as a comment on the PR — each with the exact file, the line, why it matters and how to fix it. Nothing to install for developers.

CRIT

Phantom dependencies

Packages that don't exist in PyPI or npm. Either a hallucination, or a name still unclaimed — and an open window for an attacker.
HIGH

Freshly claimed packages

They do exist — published days ago, almost no downloads. A slopsquat that has already been claimed passes every existence check. This is the one nobody catches.
HIGH

Hardcoded credentials

Eight formats, with Shannon entropy and false-positive suppression. Emails and type annotations don't trigger it.
HIGH

AI-specific flaws

LLM output rendered as raw HTML (OWASP LLM05), server secrets shipped in NEXT_PUBLIC_ variables, prompt injection sinks.
CRIT

Code and command injection

eval/exec, shell=True, SQL built by concatenation, insecure deserialization, TLS verification turned off.
FIX

The name you actually meant

When a package doesn't exist, candidate corrections are checked against the registry. Only verified names are suggested — never a guess.
03

What leaves your repository

We never store
your source code.

Diffs are analysed in memory and discarded the moment the audit finishes. Nothing about your code is written to disk — not the diff, not the findings, not the value of any credential we detect.

The only thing that leaves our server is a package name, asked of PyPI or npm. We do not download or execute the packages we check — unlike sandbox-based scanners, we only need the name.
