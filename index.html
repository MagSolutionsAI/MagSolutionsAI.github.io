Your AI assistant just invented a package.
Someone may already own it.

AI coding assistants hallucinate package names that don't exist. Attackers watch for the names that get hallucinated consistently, register them, and wait for someone to run pip install.

MagSolutionsAI checks every pull request against the real PyPI and npm registries and blocks the merge before a phantom dependency ever reaches a lockfile.

This already happened

It is called slopsquatting, and it is not theoretical.

In 2024 a security researcher noticed that AI models kept recommending pip install huggingface-cli. The real package installs differently — that name never existed.

He registered it as an empty placeholder to see what would happen. It received more than 30,000 downloads in three months. Alibaba had pasted the hallucinated command straight into the README of a public repository.

The package was harmless. It did not have to be.

Academic measurement backs it up: a study of 2.23 million AI-generated code samples across 16 models found 19.7% contained at least one hallucinated package. Rates have since fallen to roughly 5%, but 43% of hallucinated names repeat every single time the same prompt is run — which is exactly what makes them worth registering.

What it checks on every pull request

Findings arrive as a comment on the PR, each with the exact file, line, why it matters and how to fix it.

CRITICAL

Phantom dependencies

Packages added in the diff that don't exist in PyPI or npm. Either a hallucination, or an open window for an attacker to claim that name.

HIGH

Freshly claimed packages

They do exist — published days ago, almost no adoption. A slopsquat that has already been claimed passes every existence check. This is the one nobody catches.

HIGH

Hardcoded secrets

Eight credential formats, with entropy analysis and false-positive suppression. Emails and type annotations don't trigger it.

HIGH

AI-specific flaws

LLM output rendered as raw HTML, server secrets shipped in NEXT_PUBLIC_ variables, prompt injection sinks.

CRITICAL

Code injection

eval/exec, shell=True, SQL built by concatenation, insecure deserialization, TLS verification turned off.

We never store your source code

This is not a marketing line — it is how the service is built, and you can hold us to it.

  • Diffs are analysed in memory and discarded. Nothing about your code is written to disk.
  • We store metadata only: installation ID, repository name, pull request number, risk level, number of findings.
  • Detected secrets are never retained. We report where a credential is — we do not keep it.
  • Only package names leave our server. PyPI and npm are asked whether a name exists. No code is ever sent to a third party.
  • We do not download or execute the packages we check. Unlike sandbox-based scanners, we only need the name.
  • Your data is not used to train models, sold, or shared with data brokers.

Full detail in the privacy policy. Servers are hosted in Finland (EU).

What it is not

This is an automated static analysis tool and an aid to review — not a guarantee of security. It analyses only the lines added in a pull request. The absence of findings does not mean your code is secure. Every finding includes its exact location precisely so a person can verify it. It does not replace a security audit, a penetration test, or professional review.
